# SuperTuxKart Live Map Toolkit

This project adds a live race map and leaderboard layer on top of a modified
SuperTuxKart server. The Python tools receive UDP telemetry from SuperTuxKart,
draw each kart on the current track map, and save leaderboard snapshots when the
viewer closes.

The project is meant for local tournaments, classroom events, LAN setups, and
multi-server monitoring.

## What This Project Contains

| Path | Purpose |
| --- | --- |
| `projeto/make3.py` | Main live map client for one SuperTuxKart server. |
| `projeto/make3_duo.py` | Live dashboard for two servers. |
| `projeto/make3_quad.py` | Live dashboard for up to four servers. |
| `projeto/necessary_files/randomizador_grupos.py` | Optional group randomizer for tournament organization. |
| `projeto/stk-code/` | SuperTuxKart source code with the telemetry change. |
| `projeto/stk-assets/` | SuperTuxKart assets used to draw local track maps. |
| `projeto/stk-code/src/modes/world.cpp` | Modified STK source file that sends UDP telemetry. |
| `projeto/necessary_files/for_server/` | Reference copies of server files, including `world.cpp` and `my.xml`. |
| `projeto/pontuacoes/` | Saved leaderboard outputs generated by the Python viewers. |

## How It Works

The modified SuperTuxKart server sends one UDP message per kart while a race is
running. The Python viewer receives those messages, loads the matching track
layout from the local assets folder, and draws each player on a 2D map.

Current UDP packet format:

```text
track|name|kart|x|z|pos
```

Example:

```text
lighthouse|player1|tux|12.53|84.12|2
```

Fields:

| Field | Meaning |
| --- | --- |
| `track` | SuperTuxKart track identifier. |
| `name` | Player or controller name. |
| `kart` | Kart identifier. |
| `x` | Kart X coordinate in the STK world. |
| `z` | Kart Z coordinate in the STK world. |
| `pos` | Current race position reported by STK. |

The Python scripts do not download maps from the internet. They read local files
from:

```text
projeto/stk-assets/tracks/<track_id>/quads.xml
```

For that reason, the `stk-assets` folder must contain the same track that the
server is running.

## Requirements

### Python Viewer Requirements

The Python tools are intended to work on Windows, macOS, and Linux as long as
Python and `pygame` are available.

Required:

- Python 3
- `pygame`
- Network access to the machine running the modified STK server
- Local `projeto/stk-assets/` folder

### SuperTuxKart Server Requirements

To send live telemetry, the server must be built from the modified source in
`projeto/stk-code/`, or from another SuperTuxKart source tree where the same
`world.cpp` telemetry change has been applied.

Building SuperTuxKart is platform-specific. Check the official STK build
instructions in:

- `projeto/stk-code/INSTALL.md`
- `projeto/stk-code/README.md`

This README documents the project workflow, but the exact compiler packages,
CMake generator, and graphics/audio dependencies depend on the operating system.

## Install Python Dependencies

Run these commands from the repository root.

### Windows

```powershell
py -m venv .venv
.\.venv\Scripts\activate
py -m pip install --upgrade pip
py -m pip install pygame
```

### macOS and Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install pygame
```

If you do not want to use a virtual environment, install `pygame` with your
normal Python installation instead.

## Build the Modified SuperTuxKart Server

The exact build commands depend on your operating system and installed tools.
The general workflow is:

```bash
cd projeto/stk-code
cmake -S . -B build-server -DCMAKE_BUILD_TYPE=Debug -DNO_SHADERC=on
cmake --build build-server
```

On Linux, you can usually build faster with:

```bash
cmake --build build-server -j"$(nproc)"
```

On macOS, you can usually use:

```bash
cmake --build build-server -j"$(sysctl -n hw.ncpu)"
```

On Windows, the build command depends on the selected CMake generator. Examples:

```powershell
cmake --build build-server --config Debug
```

or, if using a Make/Ninja style generator:

```powershell
cmake --build build-server
```

After building, the SuperTuxKart executable is normally inside
`projeto/stk-code/build-server/bin/`, but the exact filename can differ by OS.

## Run a SuperTuxKart Server

From the STK build folder, run the server with a server config file.

Linux/macOS example:

```bash
cd projeto/stk-code/build-server
./bin/supertuxkart --server-config=my.xml --lan-server=torneio1 --network-console
```

Windows example:

```powershell
cd projeto\stk-code\build-server
.\bin\supertuxkart.exe --server-config=my.xml --lan-server=torneio1 --network-console
```

This repository currently includes a reference config at:

```text
projeto/necessary_files/for_server/my.xml
```

If your build folder does not contain `my.xml`, copy or adapt that file into the
folder where you run the server.

## UDP Ports

The current modified `world.cpp` uses fixed UDP ports:

| Port | Direction | Purpose |
| --- | --- | --- |
| `9998/udp` | Python viewer to STK server | The viewer sends `MAP_CONNECT`. |
| `9999/udp` | STK server to Python viewer | The server sends kart telemetry. |

If the viewer and server are on different machines, the firewall must allow UDP
traffic on these ports.

## Run the Single-Server Viewer

Use `make3.py` when you want to monitor one server.

```bash
cd projeto
python make3.py
```

If your system uses `python3` instead of `python`:

```bash
python3 make3.py
```

Default connection:

| Setting | Value |
| --- | --- |
| Server IP | `127.0.0.1` |
| Server UDP port | `9998` |
| Local viewer UDP port | `9999` |

If the STK server is running on another computer, change `SERVER_IP` near the top
of `projeto/make3.py`.

When the window closes, the current leaderboard is saved in:

```text
projeto/pontuacoes/
```

## Run the Multi-Server Viewers

Use these scripts when multiple STK servers are running on the same network.

```bash
cd projeto
python make3_duo.py
```

or:

```bash
cd projeto
python make3_quad.py
```

Edit `SERVER_CONFIGS` near the top of the script before running it.

`make3_duo.py` currently uses a shared `UDP_PORT` value and server entries like
this:

```python
UDP_PORT = 9999

SERVER_CONFIGS = [
    {"label": "Server 1", "server_ip": "127.0.0.1", "server_port": 9998},
    {"label": "Server 2", "server_ip": "192.168.1.20", "server_port": 9998},
]
```

`make3_quad.py` currently uses server entries like this:

```python
SERVER_CONFIGS = [
    {"label": "Server 1", "server_ip": "127.0.0.1", "server_port": 9998, "client_port": 9999},
    {"label": "Server 2", "server_ip": "192.168.1.20", "server_port": 9998, "client_port": 9999},
]
```

Change:

| Key | Meaning |
| --- | --- |
| `label` | Name shown in the dashboard. |
| `server_ip` | IP address of the computer running that STK server. |
| `server_port` | UDP port where the STK server listens for `MAP_CONNECT`. |
| `client_port` | UDP port used by the viewer. |

The current multi-server viewers use one shared local UDP socket. That means
every server should send telemetry back to the same viewer port, normally
`9999`.

## Optional Group Randomizer

The group randomizer is separate from the live map system. It does not require a
SuperTuxKart server.

Run it with:

```bash
cd projeto/necessary_files
python randomizador_grupos.py
```

or:

```bash
python3 randomizador_grupos.py
```

It asks for the number of participants, lets you enter names, and randomly
distributes them into groups.

## Find the Server IP Address

Use the IP address of the computer running the STK server.

Windows:

```powershell
ipconfig
```

macOS:

```bash
ipconfig getifaddr en0
```

Linux:

```bash
hostname -I
```

If the command shows multiple addresses, use the address for the network shared
with the viewer computer.

## Firewall Notes

If the viewer is on a different computer from the STK server, allow UDP ports
`9998` and `9999`.

Fedora example:

```bash
sudo firewall-cmd --add-port=9998/udp
sudo firewall-cmd --add-port=9999/udp
```

Windows users may need to allow the SuperTuxKart executable and Python through
Windows Defender Firewall.

macOS users may need to allow incoming network access when prompted.

## Troubleshooting

### The viewer opens but shows no map

No telemetry has arrived yet, or the received `track_id` was not found in
`projeto/stk-assets/tracks/`.

Check:

- The STK server is running a race.
- The viewer is using the correct server IP.
- UDP ports `9998` and `9999` are not blocked.
- The track exists locally in `projeto/stk-assets/tracks/`.

### `Track nao encontrada`

The Python viewer received a track name, but the matching local file was not
found:

```text
projeto/stk-assets/tracks/<track_id>/quads.xml
```

Use a track that exists in `stk-assets`, or add the missing track assets.

### `Address already in use`

Another process is already using the UDP port, usually `9999`.

Close the other viewer, stop the other process, or change the local port in the
Python script and in the STK telemetry code.

### Players do not appear

Check that the modified `world.cpp` is actually part of the STK build you are
running. A normal unmodified SuperTuxKart server will not send this project's UDP
telemetry.

### `pygame` cannot be installed

Upgrade pip first:

```bash
python -m pip install --upgrade pip
python -m pip install pygame
```

On Linux, you may also need system SDL packages from your distribution.

## Notes About Reference Files

`projeto/necessary_files/for_server/` contains reference files that can be useful
when setting up another STK source tree.

`projeto/necessary_files/make4_testing.py` is currently identical to

keep it as a backup/reference copy.

`projeto/necessary_files/pontuacoes/` is not used by the active scripts. The
active score output folder is:

```text
projeto/pontuacoes/
```

## Recommended Workflow

1. Install Python and `pygame`.
2. Build the modified SuperTuxKart source in `projeto/stk-code/`.
3. Start an STK LAN server using a server config such as `my.xml`.
4. Start a race on the server.
5. Run `projeto/make3.py` for one server, or `projeto/make3_quad.py` for several servers.
6. Close the viewer when finished to save the leaderboard output.
